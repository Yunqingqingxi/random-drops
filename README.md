# Random Drops — Minecraft 26.2 随机掉落模组

挖泥土不再只会掉泥土。**每一次掉落都会被替换成一个随机结果**：

- **67%** 概率掉出一件随机物品 —— 数量 **1~8 随机**（还会被物品自身的堆叠上限压住，剑就只有 1 把），从游戏里**全部已注册物品**中等概率抽取（含泥土自己，也含所有模组添加的物品）；
- **8%** 概率原地爆出随机生物 —— 一次最多 **3 只**，按 **敌对 50% / 中立 30% / 友好 20%** 的权重抽取，**刚爆出来的生物有 2 秒僵直**（不动不攻击，但可以被你打）；
- **25%** 概率什么都不掉（**生物死亡不会空手**，那条路把这部分概率并给了物品）；
- **保底**：同一个**物品**每 5 次掉落必定掉 1 次它的原版产物；同一种**生物**每 **3** 次击杀必定掉 1 次它的原版战利品 —— 两者都是**按对象分别计数**的（见下）；
- **击杀奖励（一场赌注）**：玩家击杀生物有 **15%** 概率**当场获得一个随机药水效果**（不产生药水物品）—— 这条线**只能靠打怪拿到**，挖方块、爆炸一律不给。其中有 **25%** 的概率掉进**负面池**，拿到的是 debuff。负面效果默认只持续 **15 秒**、有益效果 **30 秒**，所以长期是赚的，但每一次都得掂量一下。

除此之外：

- **不区分破坏方式**。玩家挖、TNT 炸、活塞推、苦力怕自爆，走的都是同一套随机规则（默认如此，可以关掉，见下）；
- **生物死亡掉落同样被替换**，但**只有玩家击杀才可能爆出新生物** —— 这是防止「生物互相残杀 → 爆出更多生物 → 继续残杀」形成指数爆炸的关键（见下）；
- **管理员 / 创造专属物品不会掉出来**：命令方块系列、屏障、光源方块、结构方块/空位、拼图方块、调试棒、知识之书、测试方块、基岩、刷怪笼、末地传送门框架等，默认已在黑名单里；
- **玩家永远不会被这个模组影响**。死亡时背包该怎么掉还怎么掉；
- 方块的经验值（挖钻石矿的 XP）也保持原版。
- **v1.11 起还多了几组「地面规则」**：刷怪蛋不再掉落、挖木头/石头有 2% 概率引燃 TNT、掉落物自动合并 +  
  每 2 分钟播报、徒手连砍木头有奖励、高处摔下来会断肢、下界/末地专属物品与末地终极物资 —— 详见下面的  
  [v1.11：五组「地面规则」](#v111五组地面规则)。
- **v1.12 起加入「附魔突破」与「全局事件」**：三个全新真附魔（**雷霆万钧** / **臭脚** / **碎裂**）+  
  定时随机全局事件（**青蛙雨** / **天降陨石**）+ 常驻 Boss 条 HUD —— 详见  
  [v1.12：附魔突破 + 全局事件](#v112附魔突破--全局事件)。
- **v1.13 起附魔突破二期**：再加四个真附魔 —— **磁石**（护甲吸掉落物）、**贪婪**（挖掘额外随机掉）、  
  **负重 / 易碎** 两枚诅咒（进 `#minecraft:curse` 标签，附魔书红字），外加「雷碎」组合演出。

## 安装

**服务器**（这是主要用法）：

1. 装好 Fabric Loader 0.19.5 的服务端；
2. 把 [Fabric API](https://modrinth.com/mod/fabric-api) 和本模组的 jar 一起放进 `mods/`；
3. 启动。首次启动会生成 `config/random-drops.json`。

**朋友那边**：这个模组**只在服务端做判定**，没有自定义渲染、没有自定义网络包，  
所以朋友用原版客户端直接连服就能玩，不需要装任何东西。  
（如果他们也想单机玩，那就各自装一份 Loader + Fabric API + 本模组。）

## 配置

文件位置：`config/random-drops.json`，首次启动自动生成。改完用 `/randomdrops reload` 生效（或重启服务器）。

> ⚠️ **从 1.8.0 及更早升级过来的话**：配置文件里已经写死了 `"mobChance": 0.15`，  
> 而磁盘上的值优先于代码里的新默认值 —— 也就是说**升级后爆怪概率不会自动降到 0.08**。  
> 请手动把它改成 `0.08`，或者直接删掉 `config/random-drops.json` 让它按新默认重新生成。  
> （新装的服务器不存在这个问题。）
>
> ⚠️ **从 1.9.0 升级过来**：`killEffectBeneficialOnly` 这个字段已经**被移除**，  
> 取而代之的是独立的 `killEffectsHarmful`（负面池）与 `killEffectHarmfulChance`（默认 0.25）。  
> 旧配置里那一行会被 Gson 忽略，效果是**打怪开始有可能吃 debuff 了** ——  
> 不想要就把 `killEffectHarmfulChance` 设成 `0`。
>
> ⚠️ **从 1.10.0 升级到 1.11.0**：新增字段会按默认值自动补齐，不用改配置。  
> 唯一需要留意的是 **TNT 引燃默认就是开的**（2%），挖木头挖石头会突然炸 ——  
> 不想要就 `"enableTntIgnition": false`。
>
> ⚠️ **从 1.11.x 升级到 1.12.0**：新增字段同样按默认值自动补齐。需要留意两点：  
> **全局事件默认就是开的**（每 10 分钟掷一次，青蛙雨刷怪、陨石会炸 terrain）——  
> 不想要就 `"enableEvents": false`；**碎裂会以 10% 概率附着在随机掉落的武器/工具上**，  
> 拿到带碎裂的武器本身就有自伤风险 —— 不想要就 `"shatterApplyChance": 0`。

## 为什么不会指数爆炸

这个模组最大的风险，是「死亡会生成新生物，新生物又制造新的死亡」这条自持循环：

```
生物死亡 → 15% 概率 × 1~3 只 爆出新生物（约一半是敌对）
        → 敌对生物去杀别的生物 → 又产生死亡 → 又爆生物 → …
```

按默认数值算它是**超临界**的：一只爆出来的僵尸一生若杀 5 只生物，而每只死亡期望爆出  
`15% × 2 = 0.3` 只，后代数就是 `5 × 0.3 = 1.5 > 1` —— 每代乘以 1.5，指数增长。  
`maxMobsPerTick` 拦不住它，因为每次死亡落在**不同的 tick**，那个上限只管单个 tick。

模组用两道措施堵死这条路：

1. **断链（关键）**：`mobSpawnRequiresPlayerKill = true`  
   只有**玩家击杀**的生物才会爆出新生物；被其它生物杀死、爆炸、火焰、摔落、自然死亡的，  
   **只掉随机物品，不爆生物**。于是每只新生物都必须由一次玩家击杀换来，  
   期望后代数 `0.3 < 1`，过程变成**次临界**，链条必然收敛。  
   （挖矿或 TNT 炸出来的生物照样会到处杀，但它们的击杀不会再生成生物。）
2. **兜底限速**：`mobSpawnRateLimit` 默认「60 秒窗口内最多 40 只」，超了就只掉物品。  
   防的是「几十个玩家同时挖矿」这类量大但正常的情况。

两层都会在自检里验一遍（见下）。

## 保底机制（按物品分别计数）

随机池里有几千件物品，所以你几乎永远抽不到「刚刚挖的那种方块」。保底就是解决这个问题的：

> **同一个物品，每 5 次掉落里必定有 1 次是它的原版产物。**  
> **同一种生物，每 3 次击杀里必定有 1 次掉它的原版战利品。**

关键在于**计数是按物品分开记的**，中间挖别的东西完全不影响：

| 你的操作 | 泥土的计数      | 石头的计数      | 掉落      |
| ---- | ---------- | ---------- | ------- |
| 挖泥土  | 1          | —          | 随机      |
| 挖石头  | 1          | 1          | 随机      |
| 挖泥土  | 2          | 1          | 随机      |
| 挖石头  | 2          | 2          | 随机      |
| 挖泥土  | 3          | 2          | 随机      |
| 挖木头  | 3          | 2（木头自己记 1） | 随机      |
| 挖泥土  | 4          | 2          | 随机      |
| 挖泥土  | **5 → 触发** | 2          | **掉泥土** |

其它细节：

- 生物那一边同样按对象计数：连杀 3 只牛，第 3 只必定掉回牛肉和皮革；中间杀猪不影响牛的计数  
  （阈值是 `mobPityThreshold`，默认 3，与方块的 5 分开配置）；
- 「原物品」取自**原版算好的掉落结果**，所以别的模组改了掉落表时，保底跟随的是改过之后的真实产物；
- 只对**玩家造成**的掉落计数（爆炸、活塞既不计数也不消耗保底）；
- 计数放在内存里，重启服务器会重置；
- `pityThreshold` 设为 `0` 即可完全关闭保底。

## 爽点：暴击大爆 + 保底可见化

「全物品等概率」有个副作用：**抽到钻石和抽到泥土一样平淡** —— 缺一个「哇」的时刻。所以加了两层反馈：

**暴击大爆**（默认每次掉落 **1%**）

- 命中时**必定**从宝藏池出，不走普通的三段分支（不会变成空手或生物）
- 金色图腾粒子 + 升级音效，并在聊天栏**全服广播**（`<玩家> 触发了暴击大爆，爆出 <物品> ×N！`）
- 宝藏池默认 17 项：钻石、钻石块、下界合金碎片/锭、远古残骸、鞘翅、附魔金苹果、不死图腾、潜影壳、下界之星、三叉戟、海洋之心、附魔书、龙息、重锤、试炼钥匙、不祥试炼钥匙
- 音效/粒子/广播都可以单独关掉；`jackpotChance` 设 0 等于关闭

**保底可见化**  
保底原本是个「暗机制」：玩家根本不知道再挖两下就能拿到原物品，期待感全浪费了。  
现在保底触发时会冒几颗友好粒子 + 一声清脆的紫水晶音 + 动作栏写明 `保底触发 · <拿到了什么> ×N`。

**稀有掉落广播**（默认关闭，把 `rareDropBroadcast` 打开）  
暴击之外，**任何稀有物品**都会一次性全服播报 —— 附魔书、各类药水、信标、骷髅头颅、海晶碎片等。  
做法是把「稀有物品」抽成一个独立判定（`DropRandomizer#isRareItem`）：**宝藏池里的算稀有，另加一张补充清单**。  
刻意**不做持久榜单**：一局就是一局，播报完就过去了。

## 末影龙通关结算

这一局的终点就是末影龙。杀掉它的那一刻，模组会：

1. 给**全服弹大标题** —— `通 关 ！` + `<玩家> 终结了末影龙`；
2. 在聊天栏摊开**本局战绩**（用时、掉落事件、拿到物品、爆出生物、什么都没掉、暴击大爆、精英怪）；
3. 在末影龙倒下的位置来一场 **24 件宝藏雨**（内容全部取自 `jackpotItems` 宝藏池）；
4. 配一套收尾音效 + 烟花/末地烛粒子。

两个刻意的设计：

- **不给任何长期奖励** —— 没有存档、没有排行榜、没有经济，所以整个模组不需要持久化；
- **只结算一次** —— 就算有人把末影龙复活再杀一遍，也不会重复触发（内部一个 `AtomicBoolean` 闸门）。

`enableFinale` 关掉即恢复成原版行为。

## 按进度调概率 + 维度 / 群系

**进度分档**（`progressScaling`）

一局制没有等级、没有装备分，唯一能反映进度的就是**世界时间**，于是直接拿它分三档：

| 档位    | 时间                              | 暴击概率倍率       |
| ----- | ------------------------------- | ------------ |
| EARLY | 0 ~ `earlyGameMinutes`（默认 20 分） | ×1（同时享用开局保护） |
| MID   | ~ `midGameMinutes`（默认 60 分）     | ×1.5         |
| LATE  | 之后                              | **×3.0**     |

进入中/后期时会在聊天栏公告一次，不然「后半段暴击变多了」这个设计玩家根本感知不到。

**维度影响**（`dimensionAffectsPools`）

| 维度  | 暴击倍率   | 专属池                                    |
| --- | ------ | -------------------------------------- |
| 主世界 | ×1     | 无                                      |
| 下界  | **×2** | 烈焰棒、岩浆膏、萤石粉、石英、远古残骸、下界合金碎片、恶魂之泪、凋灵骷髅头… |
| 末地  | **×3** | 末影珍珠、末影之眼、紫颂果、潜影壳、龙息、鞘翅、末地水晶…          |

在下界/末地时，每次掉落有 `dimensionBonusChance`（默认 25%）的概率**改从当地专属池抽** —— 跑图花的时间，掉落会认。

**群系影响**（`biomeAffectsPools`）

海洋、沙漠、丛林、沼泽、蘑菇岛、恶地、海滩这类「有特色产出」的群系，有 15% 概率改从  
`biomeBonusItems` 抽（海洋之心、海晶碎片/晶体、鹦鹉螺壳、海龟蛋、海绵、仙人掌、可可豆、竹子…）。  
群系判定用的是**id 路径子串匹配**（`biomeKeywords`），所以 `warm_ocean`、`deep_frozen_ocean` 都能被 `ocean` 命中，  
不依赖任何硬编码的群系注册表键，跨版本更稳。

倍率是**相乘**的：后期 + 末地 = `3.0 × 3.0 = ×9`，也就是 1% 的暴击在那里接近 9%。

## 击杀奖励：直接赋予药水效果（一场赌注）

玩家击杀生物时，有 **15%**（`killEffectChance`）的概率**当场获得一个随机药水效果** ——  
注意是**直接生效**，不是掉一瓶药水让你去喝。

**这不是纯奖励，是赌注。** 触发之后先掷一次 `killEffectHarmfulChance`（默认 **25%**），  
中了就走负面池：

```
[动作栏 · 紫色] 击杀奖励 · 速度 (30秒)
[动作栏 · 红色] 击杀代价 · 缓慢 (15秒)
```

两条线的音效也不同（经验球 vs 女巫喝药），所以不看文字也能立刻分辨这一把是赚是亏。

**为什么负面池的时长比有益池短一半**（15 秒 vs 30 秒）：这样长期期望仍然是正的 ——  
赌的是「这一把会不会难受一下」，而不是「打怪会不会亏」。想调得更凶就把两个时长调成一样，  
或者把 `killEffectHarmfulChance` 拉高。

**默认负面池**（8 项）：缓慢、挖掘疲劳、虚弱、饥饿、反胃、失明（8 秒）、霉运、黑暗（8 秒）。

> 刻意**没放**中毒 / 凋零 / 飘浮：那三个在残血或悬崖边是会直接要命的，  
> 而「击杀奖励」不该是个死亡陷阱。想要更刺激就自己往 `killEffectsHarmful` 里加。

### 三条硬约束

1. **只能靠击杀生物获得** —— 挖方块、TNT、活塞一律不给。想要 buff 就得去打怪；
2. **必须是玩家击杀** —— 生物互杀、摔死、烧死、自然死亡都不触发。  
   否则挂机看刷怪塔互殴就能白拿一身 buff；
3. **两个池子各自自洽** —— 有益池里写了有害效果（或反过来）会被拒绝并记日志提示你挪位置，  
   所以不会出现「有益池里混了个中毒」这种事。`NEUTRAL` 分类的效果（发光、不祥之兆之类）两边都允许。

### 效果池写法

```jsonc
"killEffects": [
  "minecraft:speed",          // 用全局时长 / 等级
  "minecraft:strength;45;1"   // 单独指定：45 秒、II 级（等级 0 = I 级）
],
"killEffectsHarmful": [
  "minecraft:slowness",
  "minecraft:blindness;8;0"   // 负面池也能单项覆盖
]
```

`killEffectDurationSeconds`（默认 30）/ `killEffectAmplifier`（默认 0 = I 级）是有益池的全局默认值，  
`killEffectHarmfulDurationSeconds`（默认 15）/ `killEffectHarmfulAmplifier`（默认 0）是负面池的。  
单项写了 `id;秒数;等级` 就以单项为准。`killEffectMaxSeconds`（默认 600）是共用安全阀，  
防止配置里写个离谱的数字把玩家永久 buff/debuff 住。

**已有同效果时不会互相覆盖**：会取「更长的时长 + 更高的等级」。所以连续触发两次速度，  
拿到的是两者里更好的那个，而不是被短的那个顶掉。

### 其它开关

| 配置                        | 默认      | 作用                            |
| ------------------------- | ------- | ----------------------------- |
| `enableKillEffects`       | `true`  | 总开关                           |
| `killEffectChance`        | `0.15`  | 每次玩家击杀生物触发概率                  |
| `killEffectHarmfulChance` | `0.25`  | 触发后掉进**负面池**的概率；设 `0` 即恢复成纯奖励 |
| `killEffectHostileOnly`   | `false` | 只对敌对生物生效（分组沿用爆怪权重那套规则）        |
| `killEffectMessage`       | `true`  | 动作栏提示拿到了什么                    |

> **极端配置也能表达**：把 `killEffects` 清空、只留 `killEffectsHarmful`，就是「打怪必定吃 debuff」；  
> 反过来把 `killEffectsHarmful` 清空就回到纯奖励。两个池子都空才会让这条线整体失效。
>
> **为什么要把爆怪概率降到 8%**：原来的 15% 实际玩下来太密了 —— 挖两下就窜出一只，  
> 洞里根本清不过来，反而挤掉了「这一下会掉什么好东西」的期待感。降到 8% 之后怪还是有，  
> 但更像「意外」而不是「常态」。打怪的动机则交给上面这条击杀奖励来补。

## 精英怪

掉落爆出来的生物有 8%（`eliteChance`）的几率变成**精英**：

- 名字变成 `精英 <原名>`，并带**发光**效果（隔着墙也能看见）；
- 生命上限 ×2（`eliteHealthMultiplier`）；
- 出生时一声咆哮 + 魂火/末地烛粒子，并**全服播报**；
- **打死当场掉 3 件宝藏**（`eliteTreasureCount`，取自宝藏池）+ 一次升级音效与图腾粒子。

三条刻意的约束：

1. **只有玩家来源才会出精英** —— 否则刷怪塔会自动量产精英，「稀罕」立刻变「日常」；
2. **不做长期奖励** —— 没有专属货币、不涨等级、不进存档，它就是一个「看到就该打」的即时爽点；
3. **识别只靠内存里的 UUID 集合** —— 一局结束进程就没了，正好符合「不考虑持久性」的前提。

精英出生时**照样吃 40 刻落地僵直**，所以不会刚爆出来就把你贴脸秒了。

## v1.11：五组「地面规则」

1.10 之前的所有改动都在**掉落表内部**做文章（换什么、换多少、概率多大）。  
1.11 第一次把规则伸到掉落表**外面** —— 掉落物落到地上之后会发生什么，玩家挖方块时会发生什么。

### 一、刷怪蛋不再掉落

刷怪蛋在随机池里是个「一键跳过游戏」的东西：给一个，僵尸刷怪笼就能量产。所以：

- 随机池**构建时**就把刷怪蛋剔除，不是「掉出来再删」—— 玩家永远不会看见它出现一帧；
- 判定走**双保险**：`instanceof SpawnEggItem`（认得所有原版蛋，包括以后新增的）  
  **加上** id 后缀匹配（`*_spawn_egg`，给不走原版类的模组蛋兜底）；
- 万一某个模组蛋两样都不沾，`extraSpawnerEggItems` 可以点名；
- 如果整个池子被筛空了（全是蛋），这一次就**什么都不掉**，而不是随便塞一个—— 宁可空手，也不给蛋。

### 二、危险方块：2% 引燃，四周甩射

挖到**原木 / 石头类 / 蜘蛛网 / 干草堆**（`tntIgniteBlocks`，支持 `#标签`）时有 2% 概率  
以挖掘点为中心朝**四个方向各甩出一枚点燃的 TNT**（`tntIgniteSpreadBlocks` = 2 格）：

- 引信 **80 刻（4 秒）**，够你转身跑两步再回头看；
- TNT 落点同时撒一把碎块（默认黑石 ×2 / 沙砾 ×2 / 泥土 ×1），爆炸总得留点痕迹；
- **同一玩家 300 秒冷却**，只对「真的引爆」计时 —— 不设冷却的话，挖矿挖得密，  
  2% 会变成「每分钟都在炸」；
- 触发时全服播报（`tntIgniteBroadcast`），附近有人时这条消息比爆炸本身更重要。

> 这一项**默认开启**。不想要就 `"enableTntIgnition": false`。

### 三、掉落物自动合并 + 每两分钟播报

**合并**：一次 TNT 连锁炸掉几百个方块，原本会掉出几百个掉落物实体。  
现在掉落物在**生成的那一刻**先看看附近（默认 2.5 格）有没有同类的一堆，有就并进去，  
直到堆满（64 或物品自身上限）。

合并的候选来自两条路：

| 来源           | 说明                                                                              |
| ------------ | ------------------------------------------------------------------------------- |
| **同刻窗口（主）**  | 自己维护一份「刚掉出来的掉落物」短名单（5 秒 / 最多 512 件）。方块破坏和爆炸的掉落都在**同一刻**连续生成，这一批彼此之间用世界查询是看不见的   |
| **世界查询（兜底）** | `level.getEntities(...)` 走区块区段存储，但它只遍历「可访问」区段；实测服务器刚起、没玩家时新生成的区段拿不到该状态，查询会稳定返回空 |

**物品不会凭空消失**：只有被**完全吸收**（数量减到 0）的那一件才取消生成，剩下多少照样生成多少。

**播报**：每 2 分钟（`dropSummaryIntervalSeconds`）在聊天栏播一次**这段时间**的掉落统计 ——  
共掉了多少件，以及数量最多的前 5 种（`dropSummaryMaxLines`）：

```
[随机掉落] 掉落统计 (最近 2 分钟，共 137 件)
  · 钻石 ×12
  · 橡木原木 ×9
  ...
```

播报完计数清零，下一条只算新的一段；这一段时间一件都没掉就不播。

### 四、徒手连挖木头触发奖励

**空着手**连挖**原木类方块**（`#minecraft:logs`）达到 **50 次**（`bareHandLogThreshold`），  
当场掉出 **8 个当前这种木头**（`bareHandLogRewardCount`）+ 播报，连击数清零重新数。

- 拿斧子挖**不算** —— 这是给「一无所有开局」的补偿，不是给效率工具的加成；
- **中途挖别的方块、或者掏出斧子，连击都会清零** —— 计数只认「一直徒手砍木头」这一件事；
- 触发后连击归零，不会连续触发两轮。

### 五、高处跌落：掉木块 + 断肢

从 **50 格**（`fallInjuryHeight`）以上摔下来（**只对玩家**）：

- 先掉一地**木块**（`fallInjuryDropItems`，默认橡木原木 ×4）—— 摔断的树，仪式感；
- 然后**断肢**：轻档（50 格）断 1 腿 + 1 手、持续 60 秒；  
  重档（`fallInjurySevereHeight` = 75 格）断 2 腿 + 2 手、持续 120 秒；
- 身上有**缓降**（Slow Falling）就不算 —— 有降落伞还摔断腿说不过去；
- **腿**管移速（`limbOnePenalty` = -30% / `limbTwoPenalty` = -80%），  
  **手**管挖掘与攻击效率（同一套比例）；
- 到点**自动恢复**；死亡、下线、关服也会立刻解除 —— 状态只在内存里，靠属性修饰符实现，不写存档。

> 手那部分只对**有「方块破坏速度」属性的实体**生效（玩家有，多数生物没有），  
> 所以自检里「手」的判定是 `有属性才必须挂上`，而不是无条件必须为 true。

### 六、分层掉落 + 末地终极物资

**分层掉落**：`netherExclusiveItems`（下界合金碎片 / 远古残骸）与  
`endExclusiveItems`（末影水晶 / 龙息）各自**只在对应维度出现**。  
在别的维度抽到它们就**重抽**，最多 8 次（`exclusiveRerollAttempts`）；  
实在抽不出来就这一次什么都不掉 —— 宁可空手，也不让专属物品漏到别的维度。

**终极物资**：在**末地**（`ultimateDimension`）每次掉落有 **1%** 概率直接产出  
**末地传送门框架 ×12 + 末影之眼 ×12** —— 正好一套，凑齐就能自己开一个末地传送门。  
这两样在正常生存里几乎拿不到（传送门框架默认就在物品黑名单里），  
所以它是这一局真正的「终点奖励」，命中时全服广播。

## 开局保护（一局制专用）

这个模组最容易毁掉的是**开局**：找不到木头做工作台、没食物、没床 —— 一局制容错率低，开局废了整局就废了。

所以**世界时间的前 20 分钟**会自动切到一套更温和的参数：

| 参数     | 正常           | 开局保护                          |
| ------ | ------------ | ----------------------------- |
| 什么都不掉  | 25%          | **5%**                        |
| 敌对生物权重 | 50（约 50% 敌对） | **10**（约 12~17% 敌对，相对更容易爆出牛羊） |
| 方块保底次数 | 5            | **3**（更快拿到木头石头）               |

窗口结束时会在聊天栏公告一次「开局保护结束 —— 从现在开始是完全随机！」。

**为什么用世界时间而不是存档里的进度标记**：你们的玩法是「打到末影龙就结束」，  
所以**世界时间 ≈ 这一局的进度**，直接拿它当判据就够，**完全不需要任何持久化**。

把 `earlyGameMinutes` 设成 `0` 即可关闭开局保护。

## 与其它模组共存

- **物品池自动包含所有模组注册的物品**：池子是直接遍历 `BuiltInRegistries.ITEM` 建的，  
  装了模组之后那些物品同样会进入随机掉落。启动日志会打印池子的构成，例如  
  `随机物品池已构建：2048 项，按命名空间：{adorn=312, minecraft=1536, promenade=200}`。
- **生物池同理**：模组添加的生物（原版分类不是 `MISC` 的）也会参与随机生成。
- 想**排除某个模组的所有物品**（比如 WorldEdit 的法杖、或某个模组的调试物品），在黑名单里写 `模组名:*`：
  ```jsonc
  "itemBlacklist": ["minecraft:air", "worldedit:*", "somemod:debug_wand"]
  ```
- 掉落表是「整体替换 + 保底放行」，其它模组对掉落表的改动会被保留（保底那一次走的正是原版路径）。
- 若某个模组自己也拦 `Block#getDrops`，两边注入会同时生效，`RETURN` 阶段更靠后的那个决定最终结果。

## 随机规则细节

- **物品池**：`BuiltInRegistries.ITEM` 的全部条目（26.2 下实测 1536 项），剔除 `itemBlacklist`。
- **随机种子**：以**毫秒时间戳**为主熵源 —— `时间戳 × 黄金比例常数 ⊕ 方块坐标 ⊕ 进程内自增序号`，  
  最后过一遍 splitmix64 做位混合，避免相邻时间戳产生高度相关的随机序列。
- **生物分类**：按顺序判断 ——
  1. 在 `neutralMobs` 里 → **中立**
  2. 在 `extraPassiveMobs` 里 → **友好**
  3. 原版 `MobCategory` 是 `MONSTER` → **敌对**
  4. 其余 → **友好**
- **候选生物**会排除 `MobCategory.MISC`（掉落物、船、画、盔甲架之类都不是生物）；  
  但只要你把它写进 `neutralMobs` / `extraPassiveMobs`，就会强制纳入。  
  村民、铁傀儡在原版正是 `MISC` 分类，所以默认用 `extraPassiveMobs` / `neutralMobs` 把它们加了回来。  
  另外生成后还有一次 `instanceof Mob` 兜底检查，抽到非生物实体就撤销它、退回掉落物品。
- **每 tick 配额**：`maxMobsPerTick` 限制一个游戏刻内最多生成多少只生物。  
  一次 TNT 连锁爆炸可能瞬间破坏几百个方块，没有这个上限足以把服务器卡死；  
  超出配额的那些方块会退化成掉落物品。

## 自检（排查用）

把 `selfTestRolls` 设成大于 0（例如 `200`），服务器启动完成后会自动在**真实的 `overworld`** 上  
把每一项功能实际跑一遍，结论（✅ / ❌ + 实测数字）直接写进日志；也可以随时用  
`/randomdrops selftest` 手动触发。

为什么挂在真服务器上而不是写单元测试：这些功能全都要摸到 `ServerLevel`、实体生成、掉落路径和广播，  
纯 mock 测不出「真的能用」。自检期间 `SessionStats` 是暂停的 —— 几百次假掉落不该污染「本局战绩」。

当前覆盖的 26 项（与上面的功能编号一一对应；① 拆成 a/b/c 三个子项）：

| 编号  | 检查内容                                                                                                                                                                                                                     |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ①-a | 物品数量实测落在 `itemCountMin~itemCountMax`，且不超堆叠上限                                                                                                                                                                             |

## 已知限制

- 只针对 **26.2**。Minecraft 从 26.x 起不再使用 Yarn 映射、官方 jar 也不再混淆，  
  但类名和包结构仍在剧烈变动（开发本项目时就接连踩到：`EntityType.getBaseClass()` 变成  
  永远返回 `Entity.class` 的残留方法、`EntityType` 的静态常量搬到 `EntityTypes`、  
  `hasPermission(int)` 被换成全新的 `PermissionCheck` API）。换版本必须重新核对 Mixin 目标签名。
- 掉落表是「整体替换」，不叠加时运/精准采集：附魔工具不会让随机结果变得更好。
- 生物死亡只替换掉落表那一层，所以生物身上的装备和死亡经验仍是原版行为。
- **掉落合并只在「掉落的那一瞬间」判定**，不做事后全场扫描。它降低的是「一次爆炸瞬间炸出几百个实体」  
  这种尖峰；「地上躺着的两堆慢慢并到一起」是原版 `ItemEntity` 自带的行为。候选来源里那条  
  `level.getEntities(...)` 世界查询依赖区块处于「可访问」状态，服务器刚起 / 没有玩家时可能返回空 ——  
  所以真正兜底的是自维护的**同刻窗口**，世界查询只当补充。
- **TNT 引燃默认开启且不看工具**：拿斧子砍原木、拿镐子挖石头一样可能炸。不想要就  
  `"enableTntIgnition": false`。
- **v1.12 的 HUD 用的是 Boss 血条（`ServerBossEvent`）**：和打龙 / 凋灵等原版 Boss 条挤在同一屏幕位置，  
  同屏出现多个 Boss 条时由客户端自行堆叠。
- **全局事件不做持久化**：重启后计时清零、进行中的事件直接消失；陨石是真实爆炸，会炸毁地形 ——  
  建筑党不想要就 `"enableMeteorShower": false` 或 `"enableEvents": false`。
- **碎裂的「厄运」会清空全身 6 格装备且不返还材料**：这是设计好的重罚，不是丢东西 bug；  
  觉得太狠就把 `shatterNegativeChance` 调低。
- **v1.13 诅咒附魔的「效果开关」管不到附魔书池子**：`enableCursedEnchantments: false` 后诅咒书  
  仍可能从随机附魔书里掉出（穿了没副作用）；想连书都绝迹需要删除数据包里的两份诅咒 json。
